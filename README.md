| Phase | Evidence from deployed v13 | Implemented change |
| --- | --- | --- |
| 1. Establish the baseline | Hatchable identified v13 as live. Its release contained 15 files and zero functions. A historical signaling route was disabled. | Archived all 15 files byte for byte and checked them against the deployment manifest. Tested the original receiver and sender together in a browser. |
| 2. Fix consent and integrity | The incoming file-start handler could create a receiver independently of an accepted offer. A transfer-complete message could display success without checking all files. Size overrun was detected after staging. | Bind each frame to the accepted offer, file order, byte limits and session. Verify actual bytes and wait for peer receipt. A modern sender waits for final batch acknowledgement. Preserve v13 compatibility in either direction. |
| 3. Bound memory and recover | Hashing called arrayBuffer on the whole file. Cleanup and receipt paths could leave staged chunks or object URLs. A disrupted receiver lost its in-memory state. | Incremental SHA-256, small send frames, adaptive buffering and verified 1 MiB checkpoints. The sender must prove it holds the saved prefix before skipping bytes. Atomic storage writes, per-file leases, quota checks and explicit cleanup protect interrupted sessions. |
| 4. Improve pairing and routing | Both peers had to exchange an offer and a reply. | 5. Build temporary signaling | v13 exchanged setup data optically. A 128 MiB browser transfer hit a real storage quota despite the browser estimating over 10 GB available. Independent IndexedDB tests reproduced the failure without BeamSync. With the final patch, a 160 MiB offer reached a real storage refusal after 113 MiB. Both peers reported the cause. - Five integrated interruption scenarios covered a partial block, a fully saved file, ordinary receipt without retention, explicit cancel and a corrupted acknowledgement. One test exposed a race when a channel started closing before its close event. - The encrypted one-scan client established a real WebRTC channel using a simulated signaling mailbox. The first handler tests used SQLite with PostgreSQL time expressions translated. The draft trial above records the subsequent checks against actual PostgreSQL.
- Layout and controls were exercised at 320, 390, 820 and 1024 CSS pixels in Chromium, including keyboard focus, trust confirmation, code image import and clipboard fallbacks. These are desktop-engine results. Native iPadOS and Android behavior requires the checks below.

## Recovery and trust in practice

1. To keep a checkpoint, select **Keep verified parts** on the receiver when accepting a file. A normal disconnect keeps verified blocks. **Cancel transfer** removes staged data. Both peers need the upgraded protocol for resume.
2. Reconnect and offer the same original file. Accept it again on the same receiving browser and origin, using the same trust context. The sender rereads the file to establish identity and confirm its prefix. Only the remaining network payload needs to cross the connection. Resume operates per file. Previously completed files in a reoffered batch can be sent again.
3. Interrupted checkpoints expire after 24 hours. BeamSync cleans them the next time it accesses that browser storage. Browser eviction, private browsing or clearing site data can remove them sooner. Closing a tab in the middle of a write can require up to 45 seconds before another tab can resume. Verified downloads are tab-scoped until you save them to Files or Downloads. [WebKit storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/)
4. To save a device, connect, choose **Compare device codes** on both screens, compare every group, then name and trust the browser. **Reconnect** pins that saved identity during a fresh pairing. Both devices must have BeamSync open. The app has no background discovery service. File receipt still requires acceptance.

## Pending decisions and device checks

**One-scan privacy and approval.** The owner approved this trial for the draft only. The Hatchable service receives encrypted setup messages and can see the clients’ IP addresses, request timing and ciphertext size. Its QR contains a secret in the URL fragment. It grants its holder the chance to pair until expiry. File contents, filenames and chat messages bypass the service. The sender requests deletion after pairing. The trial server requested a one-time cleanup after room creation. The hosted scheduler returned 404 before the cleanup handler ran. Draft 14-r7 pauses new rooms until automatic removal passes. This is an application access deadline, without a guarantee about physical deletion or platform log/backup retention. No recurring schedule, paid API or relay has been enabled.

**TURN.** STUN helps browsers find direct routes. Some mobile, corporate and guest networks block every usable direct route. A TURN relay would carry encrypted file traffic, see traffic metadata and consume bandwidth. No relay is configured. Failures on restricted networks should be recorded; approval and a bandwidth budget would precede any relay trial. [WebRTC TURN overview](https://webrtc.org/getting-started/turn-server)

## Rollback

The reviewed releases were confined to the draft and the dedicated trial table exists in the project database. The live v13 deployment requires no rollback today. The archive's `baseline-v13/public/` tree and `deployment-manifest.json` identify the exact working release from October 16, 2026 UTC. For a future software rollback, restore those public files, check all 15 SHA-256 values, dry-run the project, then release the restored build. Retain the new files as unused staged sources unless their removal is approved. Check both a fresh browser and a warmed Home Screen install. Neither restoration nor the test plan requires clearing user browser storage or deleting any database.

The trial’s additive migration defines a separate table from the v13 table. When reverting an active trial, disable room creation first and confirm the expiry cleanup removes any remaining rooms. A client-only rollback cannot undo a database migration.
